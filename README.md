## Кабінет Finance

Окремий застосунок Vue 3 з власною світло-блакитною темою Material Design.
Він не завантажує Rubick, Tailwind, jQuery, старі стилі, зображення чи JavaScript шаблону.

- `resources/views/material/app.blade.php` — мінімальна HTML-сторінка та початкові дані сесії.
- `resources/js/material/` — Vue-інтерфейс, навігація History API, JSON-запити й розрахунки.
- `resources/css/material/app.css` — незалежні стилі та адаптивна верстка.
- `app/Http/Controllers/FinanceCabinetController.php` — JSON API з валідацією та наявними моделями БД.

У Vue реалізовано вхід і відновлення пароля, вихід, роки, місячні бюджети,
категорії, створення/редагування/видалення транзакцій, серверні фільтри й пагінацію,
рекомендації бюджету за минулими витратами, календар задач, виконання/видалення задач
та перерахунок валют. Записи зберігаються через `/cabinet-api` без перезавантаження сторінки.
Фінансові дані й задачі залишаються спільними для користувачів, як у початковому застосунку.

```sh
npm run build                   # зібрати незалежні ресурси в public/material
npm run dev                     # стежити за змінами нового інтерфейсу
npm test                        # перевірити навігацію, календар, розрахунки та Vue-шаблони
DB_CONNECTION=sqlite DB_DATABASE=:memory: php vendor/bin/phpunit
```

Готові ресурси та Vue runtime включені в репозиторій; CDN і збірка для першого
перегляду не потрібні. Після оновлення Vue виконайте `npm install` і `npm run build`.
Перевірки API використовують окрему SQLite-базу в пам’яті й не змінюють робочу базу.
Нових міграцій для цього інтерфейсу немає. Старі демонстраційні та шкільні сторінки й маршрути видалені.
У `resources/` залишені вихідні файли Vue-кабінету та переклади.
Старі шкільні листи, черги й обробники видалені; відновлення пароля використовує
стандартні Laravel-сповіщення. Усі npm-команди збирають новий інтерфейс.

## Docker

Запускайте з каталогу, де знаходиться `docker-compose.yaml` (на рівень вище цього README):

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 php-www nginx-www mysql
```

Кабінет: http://localhost:81. phpMyAdmin: http://localhost:3000.
Підключення застосунку до БД визначає `Finance/.env`; Compose не перевизначає
`DB_*`. Для MySQL у цьому Compose використовуйте `DB_HOST=mysql`. Назва БД та
облікові дані мають відповідати вашій існуючій базі. На новому томі MySQL створює
базу `game` та користувача `game`; це не змінює налаштувань застосунку.
Існуючий том `mysql` збережено; MySQL 5.7 працює через
`linux/amd64`, зокрема на Apple Silicon. Не використовуйте `down -v`, якщо потрібно зберегти дані.

Якщо порти зайняті, задайте альтернативні при запуску:

```sh
FINANCE_HTTP_PORT=8081 FINANCE_MYSQL_PORT=3307 FINANCE_PMA_PORT=8082 docker compose up -d --build
```

На порожній базі застосуйте міграції окремо після запуску:

```sh
docker compose exec php-www php artisan migrate
```

PHP очікує готовності MySQL, встановлює Composer-залежності лише за відсутності
`vendor/autoload.php`, налаштовує права для кешу й логів та очищує кеш конфігурації.


## Маршрути й серверний код

- `routes/web.php` — вхід/відновлення пароля, прямі адреси Vue-кабінету,
  сесійний JSON API `/cabinet-api/*` та існуючий POST webhook Telegram.
- `routes/api.php` — зарезервований порожній файл; старі шкільні API видалені.
- `AuthController` — вхід і скидання пароля.
- `FinanceCabinetController` — початковий HTML, дані та всі дії кабінету.
- `TelegramController` — окрема існуюча Telegram-інтеграція; її сервіси збережено.

Старі CRUD-адреси, видалення через GET, діагностичні маршрути бота,
контролери Rubick/школи, Moodle/Bitrix/LiqPay-черги та старі view-composer-и видалені.
Для створення років сервер більше не залежить від старого `YearController`.


## Новий Telegram-бот Finance

Окремий бот показує загальний огляд, місячний бюджет, витрати та перевищення
за категоріями. Додавання витрати: категорія → опис → сума → спосіб оплати →
підтвердження. Автор запису визначається прив’язаним користувачем кабінету.
Статистика залишається спільною, як у вебкабінеті. Дозволені лише особисті чати з Telegram ID, прив’язаними в розділі «Користувачі»;
групові чати ігноруються. Початковий список у `.env` підтримується для сумісності,
доки прив’язка користувача не була відредагована в кабінеті.

1. Створіть окремого бота через [BotFather](https://t.me/BotFather).
2. Додайте до `Finance/.env` (токен не зберігайте в Git):

```dotenv
FINANCE_TELEGRAM_BOT_TOKEN=your_bot_token
FINANCE_TELEGRAM_WEBHOOK_SECRET=your_random_secret
FINANCE_TELEGRAM_USERS='{}'
```

3. З кореня Docker-проєкту застосуйте лише нову міграцію й очистіть конфігурацію:

```sh
docker compose exec php-www php artisan migrate --path=database/migrations/2026_10_24_170000_create_finance_telegram_tables.php --force
docker compose exec php-www php artisan config:clear
```

4. Для локальної роботи запустіть бота в окремому терміналі:

```sh
docker compose exec php-www php artisan finance:telegram poll
```

5. Відкрийте в кабінеті `/users`. Натисніть «Відкрити Telegram-бота» на картці
   потрібного користувача або у верхній панелі (для свого акаунта). Telegram
   відкриє бота з одноразовим кодом; натисніть «Старт». Бот збереже Telegram ID
   автоматично. Поле `FINANCE_TELEGRAM_USERS` заповнювати більше не потрібно.

   Альтернатива: надішліть боту `/start`, скопіюйте свій числовий Telegram ID
   і введіть його через «Ввести Telegram ID» у розділі користувачів. Порожнє
   поле відв’язує Telegram. Зміни в базі підхоплюються ботом одразу.

Команди: `/stats`, `/transactions`, `/today`, `/month`, `/add`, `/overview`, `/cabinet`, `/help`, `/cancel`.
`/transactions` показує витрати вибраного місяця по 10 записів: опис, суму,
категорію, оплату, автора й дату. Вгорі — загальна кількість та сума за місяць,
внизу — сума поточної сторінки і кнопки «Назад»/«Далі». Пагінація оновлює
повідомлення на місці; якщо редагування недоступне, бот надсилає нове.
Місяць, вибраний через `/month`, використовується для подальшої статистики та витрат.
Новий запис має поточну дату/час і належить вибраному бюджетному місяцю.

Для сервера з публічним HTTPS замість polling:

```sh
docker compose exec php-www php artisan finance:telegram webhook --url=https://your-domain.example/telegram/webhook
```

`FINANCE_TELEGRAM_WEBHOOK_SECRET` має складатися з 1–256 літер, цифр, `_` або `-`.
Webhook перевіряє секретний заголовок Telegram. Одночасно polling і webhook одного
бота не працюють; команда polling перевіряє це й не змінює налаштувань сама.
Старий `/webhook` і його інтеграція залишені окремо.

Стани діалогу та відповіді зберігаються в окремих таблицях. Повторна доставка
оновлення повторює відповідь без повторного створення транзакції. Діалог додавання
діє 30 хвилин; старі кнопки не можуть підтвердити новий запис.


### Користувачі та автоматична прив’язка Telegram

`/users` показує ім’я, пошту, ID користувача та стан Telegram. Адміністратори
(ролі 2 і 3) та початковий власник (користувач із найменшим ID) можуть управляти
всіма прив’язками. Інші користувачі бачать і редагують лише свій акаунт.

Ім’я бота визначається через Telegram `getMe`; за потреби його можна явно
вказати у `FINANCE_TELEGRAM_BOT_USERNAME` без `@`. Токен бота не передається у браузер.
Посилання `https://t.me/<bot>?start=link_<code>` містить випадковий одноразовий код
замість відкритого ID. У базі зберігається лише його хеш та відповідний ID користувача.
Код діє 10 хвилин; нове посилання скасовує попереднє невикористане. Код не можна
повторно використати з іншого Telegram-акаунта. Уже прив’язаний Telegram не можна
перенести до іншого користувача без попередньої відв’язки.

Після оновлення виконайте міграцію
`2026_10_24_180000_add_user_telegram_links.php`. Якщо polling уже запущений,
перезапустіть його один раз, щоб PHP завантажив новий код бота. Надалі редагування
Telegram ID у кабінеті не потребує перезапуску polling або змін `.env`.


### Стандартне меню Telegram

Команди з’являються у стандартній кнопці «Меню» біля поля введення.
Реєстрація виконується при запуску polling/webhook або окремо:

```sh
docker compose exec php-www php artisan finance:telegram menu
```

`/today` показує кількість і суму витрат за поточний день, суми за категоріями
та останні 10 транзакцій. День визначається в часовому поясі кабінету `app.timezone` (UTC),
без окремого зсуву для Telegram.
Цей підсумок не обмежується місяцем, вибраним через `/month`.

`/cabinet` і кнопка «Відкрити кабінет» використовують `FINANCE_TELEGRAM_CABINET_URL`
або `APP_URL`. Для відкриття з телефона вкажіть публічну HTTP(S)-адресу, наприклад:

```dotenv
FINANCE_TELEGRAM_CABINET_URL=https://finance.example.com
```

Для localhost/локальних адрес бот показує адресу текстом і пояснює обмеження,
не додаючи URL-кнопку, яку Telegram може відхилити. Після зміни `.env` очистіть
конфігурацію та перезапустіть polling.


Polling не допускає другого одночасного процесу для того самого токена: системне
блокування діє весь час роботи та автоматично звільняється після завершення процесу.
Якщо бот запущений у фоні через Docker exec, повторний ручний запуск не потрібний.


### Клавіатура з великими кнопками

`/start`, `/help` та відповіді головного меню показують постійну Telegram-клавіатуру
з вісьмома діями у чотири ряди по дві кнопки. Вона розгортається під полем
повідомлення й може перемикатися на звичайну клавіатуру штатною кнопкою Telegram.
Вибір категорії, оплати, підтвердження й пагінація залишаються кнопками під
відповідним повідомленням. Командне меню `/` також залишається доступним.


Дати транзакцій у БД залишаються в `app.timezone` (UTC). API повертає
`created_at` як ISO 8601 з явним зсувом і `created_at_local` для форми редагування.
Кабінет і бот використовують однаковий `app.timezone` (UTC). Час запису
показується як у початковому кабінеті, без додавання трьох годин; форма зберігає
введені дату та час без зсуву. Старе `FINANCE_TELEGRAM_TIMEZONE` не використовується. Існуючі записи
автоматично не зсуваються й не переписуються.


## Архітектура FinanceTelegram

`Bot` — координатор: перевіряє вхідне оновлення, виконує прив’язку/авторизацію,
передає команду процесору й доставляє відповідь. Він отримує `AccountAccess`,
`UpdateProcessor` та `TelegramTransport` через конструктор і не звертається до
HTTP, SQL або глобального контейнера.

- `Data/TelegramUpdate`, `Reply`, `CommandContext` — типізовані дані на межах компонентів.
- `Data/Conversation` і `ExpenseStage` — стан діалогу, переходи, строк дії й nonce.
- `CommandRouter` обирає першу відповідну `CommandStrategy` зі списку Laravel DI.
- `Strategies/` — окремі сценарії меню, місяців, звітів, транзакцій і витрат.
- `Reports/MonthlyReport` — спільний місячний звіт для статистики та вибору місяця.
- `Persistence/DatabaseUpdateProcessor` — блокування користувача/чату, атомарне
  збереження стану, транзакції та відповіді, повторна доставка без повторного запису.
- `Transport/HttpTelegramTransport` — Telegram HTTP API, поділ довгих повідомлень,
  клавіатури, редагування сторінок і резервна відправка нового повідомлення.
- `FinanceTelegramServiceProvider` — реєстрація залежностей і порядку стратегій.

Щоб додати сценарій, реалізуйте `CommandStrategy` (`supports` та `handle`) і
зареєструйте його з тегом `FinanceTelegramServiceProvider::STRATEGIES`.
`Bot` і маршрутизатор при цьому не змінюються. Для відображення нової дії
у клавіатурі/командному меню оновіть відповідно `MainMenu` і `CommandMenu`.
Явні команди мають пріоритет над текстовими кроками активного діалогу витрат.
Для контекстних діалогів використовується `ConversationStrategy`: маршрутизатор
виконує їх після звичайних команд, незалежно від порядку реєстрації розширень.

Формат станів та відповідей у БД збережено: початі діалоги й повторні оновлення
сумісні з попередньою версією. Нових міграцій для рефакторингу немає.
Після розгортання виконайте `php artisan optimize:clear`, щоб підключився новий
провайдер залежностей. Якщо використовується polling, перезапустіть його.
